# Как собрать

Окружение: WSL Ubuntu 24.04, 28 логических ядер, 48 ГБ ОЗУ, около 300 ГБ
свободного места на nvme. На меньшем железе тоже соберётся, просто дольше.

## 1. Дерево

    gh repo clone mamaich/GammaOSNext-RG52mini
    cd GammaOSNext-RG52mini

Это монорепозиторий: всё дерево AOSP в одном git, около 26 ГБ в `.git` и
1.2 млн файлов в рабочей копии. `repo sync` не нужен.

**Внимание на git-lfs.** Фильтр LFS обычно зарегистрирован системно, и обычный
checkout начнёт разворачивать `.repo/project-objects/**/*.pack` — пакфайлы
исходных репозиториев LineageOS, для сборки бесполезные. Правильно так:

    git config lfs.fetchexclude ".repo/**,vendor/gapps/**"
    git config lfs.concurrenttransfers 16
    GIT_LFS_SKIP_SMUDGE=1 git reset --hard HEAD
    git lfs pull --exclude=".repo,vendor/gapps"

Полезного LFS — 256 файлов на 24.6 ГБ, и без них сборка не стартует: там
`prebuilts/clang/host` (5.6 ГБ), `prebuilts/misc/common` (2.0),
`prebuilts/rust/linux-x86` (1.6), `prebuilts/jdk` (2.0), `prebuilts/sdk` (1.4).
GApps нужны только для целей `*g*` — тогда `git lfs pull --include="vendor/gapps"`.

Проверка, что ничего не осталось указателем:

    git lfs ls-files | awk '$2=="-"{print $3}' | grep -vE '^\.repo/|^vendor/gapps/'

## 2. Пакеты

Стандартный набор AOSP плюс `git-lfs`:

    sudo apt install git-lfs bc bison build-essential ccache curl flex \
        g++-multilib gcc-multilib gnupg gperf imagemagick lib32ncurses-dev \
        lib32readline-dev lib32z1-dev libelf-dev liblz4-tool libncurses-dev \
        libsdl1.2-dev libssl-dev libxml2 libxml2-utils lzop pngcrush rsync \
        schedtool squashfs-tools xsltproc zip zlib1g-dev python3 \
        python-is-python3 unzip fontconfig lz4

ccache стоит завести заранее:

    export CCACHE_DIR=~/rg52/gamma/ccache
    ccache -M 100G && ccache -o compression=true -o compression_level=1

## 3. Сборка

    export USE_CCACHE=1 CCACHE_EXEC=/usr/bin/ccache CCACHE_DIR=~/rg52/gamma/ccache
    bash buildtv_cc.sh nosync

### VNDK: искать в `/system_ext/apex`, а не в `/system/apex`

Снимки VNDK для старых vendor приезжают в образ сами: `gsi_release.mk` просит
`PRODUCT_EXTRA_VNDK_VERSIONS := 30 31 32 33 34`, а `lineage_tv_arm64_bvN.mk`
добавляет `28 29`. Апексы `com.android.vndk.v*` ставятся в
**`/system/system_ext/apex/`** — около 486 МБ, из них
`com.android.vndk.v33.apex` весит 47 МБ.

Знать это важно, потому что признаки легко прочитать наоборот. В конфигурации
выпуска `ap2a` (`build/release/build_config/ap2a.scl`) стоит
`RELEASE_DEPRECATE_VNDK = True`, отчего `envsetup.mk` берёт
`KEEP_VNDK ?= false`, `config.mk` обнуляет `BOARD_VNDK_VERSION`, а каталоги
`/system/lib64/vndk-*` остаются пустыми. По этим трём приметам напрашивается
вывод, что VNDK в образе нет. Он есть — просто не там, где его ищут.

Почему для RG52 Mini это жизненно важно: раздел vendor **не носит своих копий**
`libhidlbase.so`, `libutils.so`, `libcutils.so`, `libc++.so`, `libbase.so`,
`libhardware.so` — в `/vendor/lib64` (149 файлов) их нет вовсе, всё приходит из
`/apex/com.android.vndk.v33`, который в Android 13 отдавал раздел system.

### `KEEP_VNDK=true` ставить нельзя — устройство не загрузится

Соблазн есть: переменная добавляет в образ 28 библиотек (`libssl.so`,
`libcurl.so`, `libminijail.so`, `libaudioroute.so`, `libwifi-system-iface.so`,
`android.hardware.soundtrigger@2.0.so` и подобные) и на первый взгляд ничего не
убирает. Но вместе с ними срабатывает `build/make/core/main.mk:357`:

    ifeq ($(KEEP_VNDK)|$(PRODUCT_PRODUCT_VNDK_VERSION),true|current)
    ADDITIONAL_PRODUCT_PROPERTIES += ro.product.vndk.version=$(PLATFORM_VNDK_VERSION)

В этом дереве `PLATFORM_VNDK_VERSION` равен **35**, а снимков дальше `v34` не
существует. В `/product/etc/build.prop` попадает `ro.product.vndk.version=35`,
после чего `linkerconfig` идёт за `/apex/com.android.vndk.v35`:

    linkerconfig: Unable to access VNDK APEX at path: /apex/com.android.vndk.v35
    linkerconfig: Check failed: !"undefined var" SANITIZER_DEFAULT_PRODUCT is not defined
    linkerconfig: linkerconfig terminated by signal 6

Механика в `system/linkerconfig/generator/variableloader.cc`: не найдя апекс,
`LoadVndkLibraryListVariables()` выходит **до** того, как определит
`SANITIZER_DEFAULT_PRODUCT`, а затем `contents/namespace/productdefault.cc`
обращается к этой переменной и роняет процесс.

Дальше рушится всё: `perform_apex_config` сообщает «failed to execute
linkerconfig», `/linkerconfig/ld.config.txt` не создаётся, и ни один процесс,
которому нужны отдельные пространства имён, не стартует. На устройстве это
выглядит как бесконечный перезапуск `vendor.gralloc-4-0`, отсутствие
`surfaceflinger` и чёрный экран после логотипа.

Проверено сравнением: в сборке по умолчанию `ro.product.vndk.version` нет
вообще, а `com.android.vndk.v33.apex` в обоих образах побайтно один и тот же.

Заодно: забрать апекс с работающего Android 13 всё равно нельзя — у Rockchip он
«плоский», то есть каталог `/system/apex/com.android.vndk.current/` вместо
файла `.apex`, а Android 14 плоские апексы больше не поддерживает.

Именно `buildtv_cc.sh`, а не `buildtv.sh`: он выставляет `GAMMAOS_BOOT_GC=cc`,
и boot-образ ART собирается под read-barrier CC. В ядре RG52 Mini
`CONFIG_USERFAULTFD` выключен, поэтому ART выберет CC; собранный под uffd
boot-образ на таком ядре заставляет перекомпилировать весь boot classpath
(~15 с) при **каждой** загрузке.

Скрипт делает `lunch lineage_tv_arm64_bvN-ap2a-userdebug`, `make installclean`
и `make systemimage`, после чего кладёт результат в
`out/home/build-output/lineage-21.0-<дата>-UNOFFICIAL-tv_arm64_bvN.img`.

Проверить, что окружение живо, можно и без LFS:

    source build/envsetup.sh
    source vendor/lineage/vars/aosp_target_release
    lunch lineage_tv_arm64_bvN-$aosp_target_release-userdebug

Ожидаемый ответ: `PLATFORM_VERSION=14`, `BUILD_ID=AP2A.240905.003`,
`PRODUCT_IS_ATV=true`.

Сборку можно прерывать: ninja продолжает с места обрыва, остальное добирает
ccache.

## 4. Устройство-зависимая часть

Всё, что в Android 13 лежало в разделе `system` и теряется вместе с ним,
собрано в `device/rg52mini/`:

| Файл | Зачем |
|---|---|
| `keylayout/adc-keys.kl` | кнопки громкости (SARADC) |
| `keylayout/rk3562-joystick.kl`, `idc/rk3562-joystick.idc` | геймпад |
| `keylayout/idroid_con.kl` | внешний контроллер |
| `rg52-resize.sh`, `rg52-resize.rc` | расширение `userdata` на всю карту при первой загрузке |
| `rg52mini.mk` | всё это плюс свойства |

Подключается одной строкой в конце `device/phh/treble/lineage_tv_arm64_bvN.mk`:

    $(call inherit-product-if-exists, device/rg52mini/rg52mini.mk)

Одна строка — чтобы её было легко переносить при обновлении апстрима.

### Про свойства и порядок загрузки

`system/core/init/property_service.cpp`, `PropertyLoadBootDefaults()`: свойства
собираются в отображение, и **чем специфичнее раздел, тем выше приоритет** —
значение из более позднего файла перекрывает более раннее. Порядок:
ramdisk → `system` → `system_ext` → `vendor` → `odm` → `product`.

Отсюда два следствия:

* `ro.sf.lcd_density` в vendor равен 186, а рабочее значение 213. Перебить его
  из `system` невозможно, нужен `PRODUCT_PRODUCT_PROPERTIES` (то есть
  `/product/etc/build.prop`). Ровно так это было сделано и в Android 13.
* `ro.config.low_ram` ATV-база GammaOS ставит в `true` через
  `PRODUCT_VENDOR_PROPERTIES`; в GSI-сборке раздела vendor нет, так что в образ
  это не попадает, но на всякий случай `false` прописан явно в product.

## 5. Образ SD-карты

    bash scripts/mk-sdimg.sh [system.img] [выход.img]

Скрипт собирает полный образ:

| Что | Откуда |
|---|---|
| сектора 0…237567 | побайтно из рабочего образа Android 13: защитный MBR, GPT, idbloader (`RKNS` с сектора 64), `uboot`, `resource` и загрузочный FAT с ядром, DTB, initrd |
| `system` (p4) | собранный GSI, размер по содержимому плюс 1 МиБ |
| `vendor` (p5) | побайтно оттуда же |
| `cache`, `metadata` | пустые ext4 |
| `misc` | нули |
| `userdata` | пустой: отформатирует init, затем `rg52-resize` растянет на всю карту |

Имена разделов обязаны совпадать с оригиналом — fstab обращается к ним через
`/dev/block/by-name`.

Заодно переписывается `extlinux/extlinux.conf`: консоль ядра выводится на
uart0 (`ttyFIQ0`, 1500000 — узел `fiq-debugger` с `rockchip,serial-id = <0>`,
`earlycon=uart8250,mmio32,0xff210000`), поднимается уровень лога и добавляется
`androidboot.console=ttyFIQ0`, чтобы init поднял на этой консоли root-shell.
Для отладки первой загрузки это важнее скорости.

## 6. Отладка на устройстве

Консоль: 1500000 8n1 на тех же площадках, что использует u-boot. В Android 13
туда уже выведен logcat, так что линия проверяется без перепрошивки.
