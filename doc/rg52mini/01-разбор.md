# Разбор: устройство, исходники и как это стыкуется

Всё в этом файле проверено на живом устройстве по `adb` и на образе
`SyachOS-RG52Mini-V1.0.317m6.3.img`, а не взято из описаний.

## 1. Устройство

**AISLPC RG52 Mini**, карманная игровая консоль на Rockchip RK3562
(четыре Cortex-A55, Mali-G52).

| Параметр | Значение |
|---|---|
| Экран | 1280×720, плотность 213; панель физически портретная — `ro.surface_flinger.primary_display_orientation=ORIENTATION_90`, `fbcon=rotate:1` |
| **Сенсорный экран** | **отсутствует** |
| Органы управления | `retrogame_joypad` (геймпад и D-pad), `adc-keys` (громкость), `rk805 pwrkey`, `headset-keys` |
| Wi-Fi / Bluetooth | AIC8800D80, модули ядра + блобы в vendor |
| Носитель | SD-карта, `/dev/block/mmcblk1` |

Отсутствие тачскрина проверено `getevent -pl`: ни одного устройства с осями
многоточечного ввода. Поверх `retrogame_joypad` в vendor работает демон
`rgp2pad`, который отдаёт системе виртуальный «Xbox Wireless Controller» и
мышь по аккорду L3+R3.

## 2. Что такое GammaOS Next

Апстрим — монорепозиторий: всё дерево AOSP (LineageOS 21 / Android 14) в одном
git, около 26 ГБ в `.git`. `repo sync` не нужен, дерево уже плоское, сборка идёт
прямо из него (режим `nosync`).

Собирается только GSI, то есть `system.img`. Ни ядра, ни vendor, ни загрузчика
в дереве нет — это и делает его пригодным для чужого устройства.

Обёртки сборки:

| Скрипт | Цель | Что это |
|---|---|---|
| `build.sh` | `lineage_arm64_bvN` | «GammaOS Next Lite», обычный интерфейс |
| `buildtv.sh` | `lineage_tv_arm64_bvN` | **«GammaOS Core»**, интерфейс Android TV |
| `buildtv_cc.sh` | то же | boot-образ ART собран под ядро без userfaultfd |

Суффиксы цели читаются по схеме phh: `arm64`/`a64` — с 32-битными приложениями
или только 64-бит; `a`/`b` — разметка A-only или A/B; `v`/`g`/`f`/`o` —
vanilla / GApps / floss / microG; `N`/`S` — без root или с phh-su. То есть
`bvN` — A/B, без Google Play, без root.

Вся консольная начинка GammaOS лежит именно в TV-цели: её makefile — 14 КБ
правок (nano-лаунчер, `gammapad`, RetroArch, DraStic, PPSSPP, Flycast,
mupen64plus, Magisk, Daijishō, AuroraStore, вырезанная телефония), тогда как
не-TV цель — 1.8 КБ и почти голая. Для устройства без тачскрина выбор
однозначный.

## 3. Устройство образа и загрузка

Образ SyachOS — GPT на 4 ГБ, девять разделов:

| # | Имя | Размер | Что |
|---|---|---|---|
| p1 | `uboot` | 4 МБ | загрузчик |
| p2 | `resource` | 4 МБ | |
| p3 | `dArkOS_Fat` | 99 МБ | **FAT32**: `Image`, `rk3562-rg52mini.dtb`, `initrd.gz`, `extlinux/extlinux.conf`, `logo.bmp`, `battery_*.bmp` |
| p4 | `system` | 1.5 ГБ | ext4 |
| p5 | `vendor` | 254 МБ | ext4 |
| p6 | `cache` | 384 МБ | ext4 |
| p7 | `metadata` | 16 МБ | ext4 |
| p8 | `misc` | 4 МБ | |
| p9 | `userdata` | 1.5 ГБ, расширяется при первой загрузке | ext4 |

Загрузочный раздел — обычный FAT с обычными файлами, поэтому ядро и DTB
меняются копированием, без перепаковки образа. U-Boot читает `extlinux.conf`:

    LINUX /Image
    FDT /rk3562-rg52mini.dtb
    INITRD /initrd.gz
    APPEND console=tty1 firmware_class.path=/vendor/lib/firmware init=/init rootwait ro
           loop.max_part=7 8250.nr_uarts=10 storagemedia=sd androidboot.hardware=rk30board
           androidboot.boot_devices=ff880000.mmc androidboot.storagemedia=sd
           androidboot.mode=normal androidboot.force_normal_boot=1
           androidboot.veritymode=disabled printk.devkmsg=on loglevel=5
           fbcon=rotate:1 androidboot.selinux=permissive

`initrd.gz` — полноценный boot-ramdisk Android 13 с first-stage init. Его
`fstab.rk30board`:

    /dev/block/by-name/system   /system   ext4 ro,barrier=1  wait,first_stage_mount
    /dev/block/by-name/vendor   /vendor   ext4 ro,barrier=1  wait,first_stage_mount
    /dev/block/by-name/metadata /metadata ext4 …             wait,formattable,first_stage_mount,check
    /dev/block/by-name/userdata /data     ext4 …             wait,first_stage_mount,formattable,check
    /dev/block/by-name/cache    /cache    ext4 …             wait,check

Ни `logical` (динамических разделов нет), ни `avb=` (подпись не проверяется),
ни `fileencryption=` (`/data` не шифруется). Для подмены `system` это лучший
из возможных раскладов.

### Раздел system устроен как «system-as-root»

В корне p4 лежат `init`, `apex/`, `bin -> /system/bin`, `etc -> /system/etc`,
`dev/`, `proc/` и подкаталог `system/` с настоящим содержимым. То есть
first-stage init монтирует раздел и делает в него `switch_root`, а второй
стадией запускается уже `/system/bin/init` из нового корня — штатный путь
любого GSI.

Это важно при выборе цели сборки, см. [02-план.md](02-план.md).

## 4. Совместимость: Android 14 GSI поверх vendor от Android 13

| Проверка | Результат |
|---|---|
| `ro.treble.enabled` | `true` |
| `ro.vndk.version` | `33` |
| `ro.product.first_api_level` | `33` |
| Снимок VNDK v33 в дереве | есть (`prebuilts/vndk/v28…v34`) |
| SELinux | `permissive` через cmdline — расхождение политик A13/A14 не мешает |

HAL-ы из `/vendor/etc/vintf/manifest.xml` — всё это Android 14 поддерживает:

    audio@7.1 (HIDL)        graphics.allocator@4.0    media.omx@1.0
    audio.effect@7.0        graphics.composer@2.1     sensors@1.0
    bluetooth@1.0 (HIDL)    graphics.mapper@4.0       thermal@2.0
    camera.provider@2.4     wifi@1.0 (HIDL)           boot@1.2
    keymint / health / usb / drm — AIDL

Службы vendor, которые переживают замену `system` и нужны для работы:
`rgp2pad.rc` (геймпад), `rg52-wifi.rc`, `flydigi-*.rc`, `audio_standby.rc` и
`rg52_start_main.rc` — последний вручную делает `class_start main` и
`class_start late_start`, потому что штатный путь через событие `nonencrypted`
на этом устройстве не срабатывает.

## 5. Что теряется вместе с разделом system

Найдено перебором `/system` на живом устройстве. Всё это придётся вернуть уже
средствами сборки GSI:

* **Раскладки ввода**: `/system/usr/keylayout/{adc-keys,rk3562-joystick,idroid_con}.kl`
  и `/system/usr/idc/rk3562-joystick.idc`. Сам геймпад виден системе как
  виртуальный Xbox-контроллер от `rgp2pad`, а вот кнопки громкости (`adc-keys`)
  без своей раскладки работать не будут.
* **Расширение `userdata` на всю карту**. В SyachOS это `rg52-resize.rc` плюс
  два скрипта и управляющий APK `RG52StorageResize`, и всё лежит в `system`.
  Механизм двухступенчатый: `sgdisk` растягивает девятый раздел до конца карты
  (после чего нужна перезагрузка, чтобы ядро перечитало таблицу), затем
  `resize2fs` в онлайне растягивает файловую систему уже смонтированного
  `/data`.

## 6. Сборщик мусора ART и ядро

`buildtv.sh` собирает boot-образ ART под userfaultfd/CMC, `buildtv_cc.sh` — под
read-barrier CC. Коллектор выбирается **ядром**, и несовпадение стоит около
15 секунд перекомпиляции boot classpath **на каждой загрузке**.

В ядре устройства:

    # CONFIG_USERFAULTFD is not set

При этом `include/uapi/linux/userfaultfd.h` в исходниках 5.10.226 уже содержит
и `UFFD_USER_MODE_ONLY`, и `UFFD_FEATURE_MINOR_SHMEM` — поддержку можно
включить одной строкой конфига и перейти на быстрый вариант. Пока ядро не
тронуто, поэтому собирается `buildtv_cc.sh`.
